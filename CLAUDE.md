# SpecterRealm Core — AI Context

## What This Is

NeoForge 1.21.1 library mod (`mod_id: specterrealm`) providing shared crafting components, icon items, and the Field Manual Patchouli book for Colony Protocol modpacks. Not a standalone gameplay mod — it fills recipe-gating gaps and standardizes crafting intermediates across packs.

**Required dependency:** Patchouli (loaded AFTER specterrealm)
**Optional integrations:** EMI (recipe viewer, compileOnly), JEI (pending SR-809)

## Tech Stack

- **Mod loader:** NeoForge 21.1.172
- **Minecraft:** 1.21.1
- **Java:** 21 (JDK 21, Temurin)
- **Build:** Gradle 8.8 with NeoForge Gradle plugin 7.0.145
- **Package:** `com.specterrealm.core`
- **Main class:** `src/main/java/com/specterrealm/core/SpecterRealmCore.java`

```
│   ├── MaterialSets.java          # Named EnumSet groups used by SpecterPart declarations

│   └── ItemInit.java              # Data-driven registration loop + creative tab
└── compat/
    └── emi/
        └── SpecterEmiPlugin.java  # EMI plugin — hides config-disabled items from item list
```

## Design (Iris)

The mod's design lives in the Iris SpecDoc **`specterrealm-core`** (product `cp`): config gating, current items, the 18 materials, SpecterPart naming rules, `c:` convention tags, the Field Manual, and planned work. Read it with the Iris MCP tools (`iris_specdocs_spec`, then `iris_specdocs_section`) and edit it there. The last copy kept in this file is `git show e4154ce:CLAUDE.md`.

Two rules agents need while coding:

- `materialPrefix = true` → item ID `{material.id}_{part.id}` (e.g. `iron_spur_gear`); `false` → `{part.id}`, gated on the material config, or on the category config alone when the part has no materials.
- Items are always registered (the registry freezes before config loads); config only hides them (creative tab, EMI, later JEI and recipe conditions).

## Adding a New Part

1. Add entry to `SpecterPart.java` — specify id, category, materialPrefix flag, and material set from `MaterialSets`
2. Run `python3 scripts/generate_assets.py` — creates model JSON, lang entry, and tag files
3. Add texture PNG to `assets/specterrealm/textures/item/<name>.png`
4. Add recipe JSON to `data/specterrealm/recipes/<name>.json` (if craftable at a table)

## Adding a New Material

1. Add enum constant to `SpecterMaterial.java` with id and config supplier
2. Add `BooleanValue` field to `SpecterRealmConfig.java` under `[materials]`
3. Add the material to relevant sets in `MaterialSets.java`
4. Run `python3 scripts/generate_assets.py`
5. Add texture PNGs for all new `{material}_{part}` combinations
6. Add `data/c/tags/item/ingots/{material}.json` if the material isn't provided by another mod

## Asset Generator

`scripts/generate_assets.py` — run from repo root to regenerate all data files.

**Generates:**
- `assets/specterrealm/models/item/*.json` — one per item
- `assets/specterrealm/lang/en_us.json` — all display names
- `data/specterrealm/tags/item/crafting_parts.json` — master tag
- `data/specterrealm/tags/item/{category}_parts.json` — per-category tags
- `data/c/tags/item/{category}/{material}.json` — convention tags

**Does NOT generate:** textures (artwork), recipes (design decision needed per part).

Always re-run after modifying `SpecterPart`, `SpecterMaterial`, or `MaterialSets`.
